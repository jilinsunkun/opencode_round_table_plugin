# 脑暴项目文件职责重构落地清单

## 目标

把重复定义收敛为单一事实源（SSOT），并把规则、入口、角色、执行、配置、产物、运行态分离，降低维护漂移。

## 范围

本次只处理以下文件：

- `.opencode/brainstorm/state-card-rules.md`
- `.opencode/agents/brainstorm-host.md`
- `.opencode/commands/brainstorm.md`
- `.opencode/plugin/brainstorm-orchestrator.ts`
- `.opencode/opencode.json`
- `.opencode/brainstorm/state-card.md`
- `.opencode/brainstorm/registry.json`

## 不做什么

- 不重写整体脑暴流程设计
- 不新增角色
- 不引入复杂规则 DSL
- 不做自动双向生成
- 不做大规模重构其他无关文档

## 完成标准

- 规则正文只存在于 `state-card-rules.md`
- 其他文件只保留最小必要上下文和短引用
- `plugin/brainstorm-orchestrator.ts` 只做执行、校验、写入，不承载第二套规则正文
- `state-card.md` 只作为插件生成产物存在
- `registry.json` 只保存运行时状态，不混入职责说明

## 文件级任务卡

### F01 `.opencode/brainstorm/state-card-rules.md`

- **当前职责**：规则正文分散，承担状态卡规则说明
- **目标职责**：唯一规则源 + 契约源
- **处理方式**：重写 / 收敛 / 合并
- **依赖**：无
- **风险**：SSOT 写太胖
- **验收标准**：
  - 仅此文件包含完整规则正文
  - 包含字段契约、映射契约、行为契约
  - 包含版本说明与兼容性说明
  - 包含输出格式与纪律边界
- **具体动作**：
  1. 补规则边界与适用范围
  2. 增加字段契约区
  3. 增加字段名映射表（中文字段 ↔ 代码字段）
  4. 增加版本 / 兼容性说明
  5. 保留输出格式与压缩规则
  6. 删除与入口、角色、执行重复的说明文字
- **回滚方式**：恢复删除前的规则段落

### F02 `.opencode/agents/brainstorm-host.md`

- **当前职责**：主持人角色说明中夹杂流程与规则
- **目标职责**：角色壳 / 行为边界层
- **处理方式**：精简 / 删除重复 / 改引用
- **依赖**：F01
- **风险**：角色说明过薄导致可读性下降
- **验收标准**：
  - 只保留身份、职责边界、短引用
  - 不再复述完整流程、状态卡字段、收敛规则
  - 文件长度控制在一页内
- **具体动作**：
  1. 删除完整流程定义
  2. 删除状态卡字段全文
  3. 删除收敛规则全文
  4. 删除轮次协议全文
  5. 保留一句 SSOT 引用
  6. 只保留少量角色专属边界
- **回滚方式**：恢复原角色描述段落

### F03 `.opencode/commands/brainstorm.md`

- **当前职责**：入口说明中混入流程正文
- **目标职责**：入口层 / 最小使用说明
- **处理方式**：压缩 / 删除流程 / 改引用
- **依赖**：F01
- **风险**：入口说明过短导致新人难以理解
- **验收标准**：
  - 只保留命令用途、触发方式、最小启动说明
  - 不包含流程正文、状态卡字段清单、多轮策略
  - 使用示例不超过 1-2 个
- **具体动作**：
  1. 删除详细流程步骤
  2. 删除状态卡字段列表
  3. 删除角色分工重复说明
  4. 保留一句规则引用
  5. 保留最小启动说明
- **回滚方式**：恢复原 command template

### F04 `.opencode/plugin/brainstorm-orchestrator.ts`

- **当前职责**：既有执行逻辑，也有规则叙述和模板文字
- **目标职责**：执行层 / 守门层 / 校验层
- **处理方式**：薄化 / 删叙述 / 保留校验
- **依赖**：F01
- **风险**：插件逻辑膨胀成隐性规则源
- **验收标准**：
  - 仅保留主题初始化、会话创建、registry 读写、state-card 同步、生命周期处理、运行时校验
  - 不再包含第二套规则正文
  - 不再解释规则，只消费契约
- **具体动作**：
  1. 删除规则解释性叙述
  2. 删除与 SSOT 重复的策略说明
  3. 保留必要的字段默认值补全
  4. 保留写入与落盘逻辑
  5. 校验字段一致性、模板顺序一致性、落盘一致性
- **回滚方式**：恢复旧模板与旧校验逻辑

### F05 `.opencode/opencode.json`

- **当前职责**：注册/装配配置中混入流程正文
- **目标职责**：注册层 / 装配层 / 配置层
- **处理方式**：收紧 / 删除说明文本
- **依赖**：F01, F04
- **风险**：配置文件再次长出业务规则
- **验收标准**：
  - 只保留 agent 注册、command 注册、plugin 挂载、权限配置、默认入口
  - 不出现流程正文、规则正文、说明性长文
- **具体动作**：
  1. 删除流程正文
  2. 删除规则正文
  3. 删除业务解释性文本
  4. 只保留机器配置
- **回滚方式**：恢复原配置文本

### F06 `.opencode/brainstorm/state-card.md`

- **当前职责**：运行态文档，同时可能被误认为规范源
- **目标职责**：生成产物 / 人可读运行态视图
- **处理方式**：声明产物 / 约束格式
- **依赖**：F01, F04
- **风险**：被手工改写成规范源
- **验收标准**：
  - 只保留议题 ID、当前问题、主方案、否决方案、争议、待验证点、下一轮问题
  - 明确声明它是插件生成产物
  - 不包含任何规则正文
- **具体动作**：
  1. 明确文件为生成产物
  2. 固定字段顺序
  3. 禁止手工维护为规范源
- **回滚方式**：恢复原 state-card 模板

### F07 `.opencode/brainstorm/registry.json`

- **当前职责**：运行时状态存储，同时可能混入说明
- **目标职责**：运行时状态存储 / 机器可读状态
- **处理方式**：声明状态 / 保持最小化
- **依赖**：F01, F04
- **风险**：运行时状态膨胀成说明文档
- **验收标准**：
  - 只保留版本、activeTopicId、bootstrappingTopicId、topics、历史摘要、压缩记录、锁状态
  - 不混入职责说明或规则正文
  - 字段与 SSOT 契约一致
- **具体动作**：
  1. 删除说明性文本
  2. 保持运行态字段最小化
  3. 对齐字段契约
- **回滚方式**：恢复原 registry 数据结构

## 回滚原则

- 每个文件任务都能独立回滚
- 任何一步失败都先停，不连带删除下一步依赖文件

- 校验未通过前，不收紧入口到空壳
