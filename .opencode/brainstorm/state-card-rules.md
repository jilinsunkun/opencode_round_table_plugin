# 状态卡更新规则（SSOT）

> 规则正文的唯一权威源。其他文件只允许短引用，不得复写本文件内容。

## 1. 适用范围

本规则只约束脑暴流程中的「状态卡」：

- 何时更新
- 更新哪些字段
- 字段如何映射到代码与 Markdown
- 压缩时保留什么、丢弃什么
- 输出格式与纪律边界

状态卡的职责只有一个：把上一轮讨论压缩成下一轮可以直接续接的最小信息单元。

## 2. 更新时机

由主持 Agent 在每轮结束后统一更新。

触发更新的典型时机：

- 发散轮结束
- 挑刺轮结束
- 工程评估轮结束
- 研究补充轮结束
- 上下文接近上限，需要压缩续航

## 3. 输入来源

状态卡只吸收能改变下一轮决策的信息，来源包括：

- 发散 Agent：新方案、替代路径、补充视角
- 挑刺 Agent：漏洞、边界条件、失败场景
- 工程 Agent：落地成本、实现路径、验证难度
- 研究 Agent：事实、案例、外部依据

背景叙述、重复表达、长篇纪要，默认不写回状态卡，只保留在历史摘要中。

## 4. 结构契约

### 4.1 必保字段

状态卡必须按以下顺序出现：

1. 当前问题
2. 当前主方案
3. 已否决方案
4. 关键争议
5. 仍待验证点
6. 下一轮需要回答的问题

### 4.2 字段语义

| Markdown 标题 | 代码字段 | 语义 |
| --- | --- | --- |
| 当前问题 | `currentQuestion` | 当前要讨论的核心问题 |
| 当前主方案 | `currentMainProposal` | 当前优先推进的方案 |
| 已否决方案 | `rejectedProposals` | 已明确放弃或降级的方案 |
| 关键争议 | `keyConflicts` | 目前仍未消解、且影响结论的争议 |
| 仍待验证点 | `openQuestions` | 仍需要事实或实验验证的问题 |
| 下一轮需要回答的问题 | `nextRoundQuestions` | 下一轮必须先回答的问题 |

### 4.3 变更纪律

- 能改变结论的新信息，写入状态卡。
- 只是重复描述的信息，不写入状态卡。
- 只是背景说明的信息，进入历史摘要，不写入状态卡。
- 已否决方案不要复活，除非出现新的关键证据。
- 争议项必须写成可验证的问题，避免情绪化表述。

## 5. 映射契约

### 5.1 从四类角色到状态卡

| 输入角色 | 优先写入位置 | 处理要求 |
| --- | --- | --- |
| 发散 Agent | `currentMainProposal` / `rejectedProposals` / 备选脉络 | 只保留真正新增的路径 |
| 挑刺 Agent | `keyConflicts` / `openQuestions` | 把风险转成可验证问题 |
| 工程 Agent | `currentMainProposal` / `openQuestions` | 如果更短、更稳或更可落地，则更新主方案 |
| 研究 Agent | `keyConflicts` / `openQuestions` / 历史摘要 | 只有能改变判断的证据才写回 |

### 5.2 从状态卡到运行态

历史摘要进入 `registry.json`，状态卡保留当前仍有效的信息。

压缩后仍必须能回答四个问题：

- 我们在讨论什么？
- 现在主方案是什么？
- 为什么还有争议？
- 下一轮该验证什么？

## 6. 压缩规则

当上下文接近上限时，主持人执行压缩：

1. 保留必保字段
2. 删除重复叙述
3. 删除已失效的背景说明
4. 只保留当前轮仍然有效的信息
5. 历史细节进入 `registry.json` 的 history 摘要

## 7. 输出格式

状态卡必须使用以下 Markdown 结构，字段顺序不可变：

```markdown
# 状态卡

> 由插件生成，禁止手工维护；格式受 `.opencode/brainstorm/state-card-rules.md` 约束。

> 当前议题 ID：...

## 当前问题
...

## 当前主方案
...

## 已否决方案
- ...

## 关键争议
- ...

## 仍待验证点
- ...

## 下一轮需要回答的问题
- ...
```

## 8. 版本与兼容性

- 版本号遵循 `state-card-rules.md` 自身的语义版本管理。
- 任何字段增删改，都必须先更新本文件，再同步代码与产物格式。
- 旧版本状态卡在读取时应尽量向下兼容，但写回时必须按当前契约输出。

## 9. 纪律边界

- 状态卡不是完整纪要。
- 状态卡不是角色口吻说明。
- 状态卡不是执行流程说明。
- 状态卡只允许保存下一轮决策所需的最小信息。
